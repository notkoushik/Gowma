# Gate 1 — Identity, authentication, and sessions

- Login rejects incorrect passwords.
- Login rejects inactive users.
- Registration stores only password hashes.
- User APIs never return passwords or password hashes.
- JWTs contain only minimal identity and scope claims.

- Tokens expire.
- Password changes invalidate old sessions.
- Role changes invalidate old sessions.
- Account deactivation invalidates old sessions.
- Login is rate-limited.
- Unknown users cannot be auto-created through login.
- Missing/invalid JWT returns `401`.

# Gate 4 — Hold lifecycle

Hold state must be explicit:

```text
ACTIVE
CONSUMED
RELEASED
EXPIRED
```

## Required behavior

- Hold requires authenticated customer.
- Hold stores customer ID.
- Hold stores animal ID.
- Hold stores date/start/duration.
- Hold TTL is bounded.
- Overlapping active holds are rejected.
- Overlapping bookings are rejected.
- Only owner can release a hold.
- Admin support release is audited.
- Consumed hold cannot be released.
- Released hold cannot be reused.
- Expired hold cannot create a booking.
- Failed payment releases or expires the hold correctly.

## Concurrency tests

```text
two customers request same slot -> exactly one succeeds
same customer sends duplicate hold requests -> exactly one succeeds
two overlapping duration requests -> exactly one succeeds
hold expires while booking request is in flight -> booking rejected
release and booking race -> exactly one terminal state
hold cleanup does not release another customer's hold
```
